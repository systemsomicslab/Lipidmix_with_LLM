### 3.2 ピーク注釈の生化学的検証機能（2026-07-02）

MS-DIALが付与した脂質名や分子式を、そのまま確定同定として扱う誤りを避け、質量誤差、アダクト、イオンモード、脂質クラスの整合性を説明可能な形で確認するため。

#### 何を

- 分子式パーサーとモノアイソトピック質量計算を追加した。
- アダクトから理論m/zを計算し、観測m/zとのppm誤差を評価できるようにした。
- アダクトと正負イオンモードの整合性を判定できるようにした。
- 脂質クラス語彙、エーテル脂質表記などの注意点を追加した。
- MCPツール `verify_peak_annotation` を追加した。

#### どうやって

- 分子式、アダクト、イオンモードの判定をMCP非依存の純粋関数へ分離した。
- 判定不能なケースを無理に合否判定せず、`UNKNOWN` として返す安全側の設計にした。
- 精密質量、アダクト整合、名称上の注意点を一つの検証ドシエとして構造化した。
- 単体テストを段階的に追加し、非極性・未知イオンモードなどの境界条件も確認した。

### 3.3 科学的前処理・QC・差次的解析・同定信頼度（2026-07-02〜2026-07-03）

#### なんのために

生のピーク強度を直接PCAや群間比較へ投入するだけでは、測定量差、ブランク背景、装置ドリフト、QC不良、欠損値、多重検定などにより誤った結論を出す可能性があるため。解析前提と注意点を明示し、再現可能な統計解析に近づけることを目的とした。

#### 何を

- `arf_list_sample_roles`: sample/QC/blankの分類確認。
- `arf_preprocess`: ブランクフィルタ、TIC/median/PQN正規化、QCドリフト補正、QC RSDフィルタ、欠損補完。
- `arf_pca_preprocessed`: 前処理後行列を使うPCA。
- `arf_differential`: 2群Welch t検定、log2 fold change、Benjamini-Hochberg FDR、volcanoデータ。
- バッチ交絡、小標本、正規化状態などのcaveat出力。
- GOSLINによる脂質名正規化、RefMet/LIPID MAPS対応、保守的なMSIレベル推定。

#### どうやって

- 行がサンプル、列が「スポット×定量値」の正準行列を `AnalysisSession` に保持した。
- 前処理は、失敗QC診断、ブランク判定、正規化、QCドリフト補正、QC RSD判定、欠損補完の順に適用する純ロジック層として実装した。
- QC不足、注入順不足、正規化不能、過度な特徴量除去を無言で処理せず、JSONの `caveats` に記録した。
- 差次的解析ではp値だけでなくFDRと効果量を併記し、統計的有意性と生物学的差の両方を評価できるようにした。
- 実際の疎なデータで正規化係数が0になるケースや、全欠損列、群とバッチの交絡をテストした。
- 多群ANOVAは一度実装したが、MS-DIALメタデータだけでは因子と水準の対応を安全に決定できないため、現在のMCP公開面では封鎖し、明示的な2群比較を標準とした。

### 3.5 ローカルLLMルーティングと解釈品質評価（2026-07-06〜2026-07-09）

#### なんのために

全MCPツールを常にLLMへ提示するとプロンプトが肥大化し、誤ったツール選択が増える。また、モデル選択を印象ではなく、実データに対する解析判断の正確さで比較する必要があったため。

#### 何を

- 解析フェーズ別に提示ツールを絞るphase routerを実装した。
- 1ターン内のツールループ回数を制限したローカルLLM agent loopを実装した。
- 凍結済みMCP出力を使う盲検比較・採点ハーネスを作成した。
- NEG/POS、PCA、QC、差次的解析、文献探索を含む評価ケースを整備した。
- 高価値ターンだけクラウドモデルへ最終解釈を切り替える2段構成を試験した。
- PCA、差次的解析、文献検索などのMCP応答をスリム化した。

#### どうやって

- キーワード、状態ゲート、ローカルLLM分類、フォールバックを組み合わせ、フェーズごとの許可ツール集合を決定した。
- モデル名を伏せたA/B比較と絶対採点を行い、同一の凍結ツール出力でモデル間を比較した。
- `arf_differential` の全volcano点列や、PCAの大きな座標配列、文献抄録全文をそのままLLMへ渡さず、要約・上位特徴・必要情報を保持した構造に変更した。
- 8,000文字上限を監査する回帰ハーネスを追加した。
- 研究用のagent/evaluation試作コードは、解析MCP本体の保守性を下げないよう最終的に `archives/` へ退避し、後の `Use-LLLM` 分離につなげた。

### 3.6 ARF解析の実運用機能強化（2026-07-09〜2026-07-10）

#### 何を

- PCA結果へクライアント描画用座標JSONを含めた。
- Class IDの部分トークンを使ったプール群比較を追加した。
- 失敗QC、QC注入の偏り、複数QC層を検出してcaveatへ出すようにした。
- ARF2由来の名称補完と、差次的解析結果の説明性を改善した。

#### どうやって

## 6. 残課題と注意事項

### 配布

- `Use-LLLM-Setup.exe` は現在Authenticode署名がなく、検証時点では `NotSigned` である。研究室配布時にはSmartScreen警告と配布元確認が必要になる。
- Ollama本体とモデルはインストーラーへ同梱していないため、別途導入・取得が必要である。
- 新規環境では外部MCPを0件で開始するため、`ms-data-parser` は必要な利用者が追加登録する。

### 解析

- 多因子ANOVA、交互作用、共変量調整モデルは未提供であり、現在は明示的な2群比較を標準とする。
- Class ID略語の意味は自動確定せず、候補提示と利用者確認を継続する必要がある。
- QCが測定列へ適切に挿入されていないデータでは、QCドリフト補正は成立しない。
- 複数の組織別QCや複数バッチを一系列として扱う補正は近似であり、caveatを解釈時に必ず確認する必要がある。

### `Use-LLLM`

- Knowledgeへの保存・添付基盤は実装済みだが、引用付きRAG、埋め込み、再ランキング、Office/PDF抽出は未実装である。
- クラウドLLMプロバイダーの一般対応、複数ユーザー認証は今回の対象外である。
- 2026-07-15のGUI・Knowledge・インストーラー関連実装は、報告書作成時点で `Use-LLLM` の作業ツリーに未コミット変更を含む。次の区切りでは、現行102件のテスト結果を維持したままコミット単位を整理する必要がある。
